# Legal AI API

Описание архитектуры API-сервиса Legal AI.

## Основные модули

| Путь | Назначение |
|------|------------|
| `app_core/application.py` | Контейнер настроек и фабрика FastAPI-приложения. |
| `app_core/dependencies.py` | Функции доступа к контейнеру и сервисам анализа. |
| `app_core/routes/analyze.py` | Основные эндпоинты анализа документов и генерации ответов. |
| `app_core/routes/health.py` | Health-check и технические служебные маршруты. |
| `app_core/routes/connectivity.py` | Сетевые проверки и загрузка документов по URL. |
| `app_core/rag/` | Ингест и поиск по корпусу НПА в Qdrant. |
| `app_core/llm/` | Обёртки над Ollama и моделями генерации. |
| `app_core/startup.py` | Регистрация событий `on_startup` и `on_shutdown` (инициализация индексов, прогрев моделей). |

## Поток обработки запроса анализа

1. **Маршрут `/analyze`.** Обработчик принимает текст документа и параметры запроса.
2. **Инжекция зависимостей.** Из контейнера извлекается сервис анализа (`LegalAIService`).
3. **Векторизация и поиск.** Запрос проходит через Qdrant для поиска релевантных фрагментов базы знаний.
4. **Генерация ответа.** Ollama формирует осмысленный ответ и список рекомендаций.
5. **Формирование отчёта.** Pydantic-модель приводит результат к стандартизованному виду.

## Расширение

* Дополнительные источники знаний подключаются через новые провайдеры в `app_core/startup.py` и зависимости в `app_core/dependencies.py`.
* Чтобы добавить новый маршрут, создайте модуль в `app_core/routes/` и зарегистрируйте его в `app_core/api/__init__.py`.
* Для написания юнит-тестов можно инициализировать контейнер с тестовыми настройками и подменными клиентами.
