# Contract Extractor

Документ описывает ключевые компоненты сервиса извлечения данных из договоров после рефакторинга.

## Основные модули

| Путь | Назначение |
|------|------------|
| `application.py` | Сборка контейнера, создание приложения и регистрация маршрутов. |
| `dependencies.py` | FastAPI-зависимости: доступ к контейнеру, проверка схемы, запуск конвейера извлечения. |
| `api/routes/extraction.py` | Основные HTTP-маршруты (`/check`, `/summary`), работающие с текстом договора. |
| `services/extractor/pipeline.py` | Конвейер обработки текста и обращения к Ollama. |
| `core/` | Конфигурация, схемы, валидатор и настройки полей. |

## Поток обработки запроса `/check`

1. **Валидация входных данных.** Pydantic-модель проверяет текст договора и опциональные параметры.
2. **Проверка схемы.** Зависимость `get_schema_validator` сверяет структуру результата с базовой схемой.
3. **Извлечение полей.** `ExtractionPipeline` комбинирует промпты, обращается к Ollama и возвращает сырые ответы модели.
4. **Постобработка.** Результат приводится к договорной схеме и возвращается клиенту.

## Настройка и расширение

* Новые поля добавляются через файлы в `prompts/fields/` и конфигурацию `assets/field_extractors.json`.
* Для тестирования можно подменить `OllamaClient`, передав фейковую реализацию через контейнер.
* Бизнес-правила удобно оформлять как отдельные функции внутри `pipeline.py` или дополнительного сервиса.
